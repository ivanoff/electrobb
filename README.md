# electrobb

A Bun service that monitors Telegram power-outage updates and sends Ukrainian alerts with schedule changes, reminders, and configurable quiet hours.

Сервис на Bun получает данные у `@ChernigivOEbot` и пишет понятные уведомления **на украинском языке** в канал **😱AAA**. Все даты и время считаются по **Europe/Kyiv**, независимо от часового пояса компьютера.

## Какие отключения учитываются

В расчёт входят:

- **Заходи обмеження** — плановое отключение.
- **Графіки аварійних відключень (ГАВ)** — аварийное отключение.
- Отдельные сообщения «повідомляє про планову перерву в електропостачанні» для настроенного лицевого счёта со статусом «РОБОТИ ЗАПЛАНОВАНО» — плановое отключение.

**Исключены** «Виконання оперативних перемикань» и «Виконання ремонтних робіт на обладнанні підстанції …». Исключение действует и тогда, когда такая причина указана внутри отдельного сообщения о плановой перерыве.

Другой тип в графике, например **Графік погодинних відключень (ГПВ)**, не добавляется в расчёт. Сервис один раз сообщает в канал о каждом неизвестном типе, чтобы можно было уточнить правила. Во время тишины это сообщение ждёт до утра. Номер лицевого счёта и адрес в уведомления не включаются.

## Как строится расписание

Сначала учитываемые интервалы объединяются, если они пересекаются или соприкасаются. Например, плановое отключение 12:00–14:00 и аварийное 11:00–16:00 дают одно отключение **11:00–16:00 (планове та аварійне)**.

Сервис предупреждает о начале в 11:00 и об окончании в 16:00. Напоминаний о внутреннем начале в 12:00 или включении в 14:00 не будет. Исключённые ремонтные работы не удлиняют объединённый интервал.

Уведомления отправляются только о сегодняшних предстоящих или уже начавшихся интервалах. Переходящий через полночь интервал учитывается, если он ещё идёт. Исключение для будущей даты: об отключении на ближайшее тихое время предупреждаем заранее, пока отправка разрешена (см. ниже). Остальные будущие даты сохраняются до соответствующего дня; завершившиеся отключения не рассылаются заново.

## Когда приходят сообщения

1. **Как только обнаружен новый интервал** — его начало, конец и вид отключения.
2. **За час до начала** — напоминание. Если информация появилась позже, сообщение сразу указывает оставшиеся минуты. Отдельное дублирующее часовое напоминание в этом случае не отправляется.
3. **При изменении конечного времени объединённого интервала** — сообщение со старым и новым временем. Если новое время уже прошло, сервис сообщает, что по обновлённому графику интервал завершился. Это сведения графика, а не измерение наличия электричества.
4. **За 15 минут до конца** — сначала проверка свежего графика, затем «За оновленим графіком скоро ввімкнуть світло (о 22:00)». Если время перенесено, приходит сообщение о переносе, а проверка перед включением переносится на новый срок.

Одинаковые результаты очередной проверки не рассылаются повторно. Отправленные напоминания и ограничения запросов сохраняются в `cache/state.json`, поэтому перезапуск не обнуляет их.

Если новая информация сдвинула начало на более раннее время, уведомление строится по новому объединённому интервалу. Старые уже отправленные сообщения остаются в канале, но напоминаний по устаревшему началу больше не будет.

## Как часто сервис обращается к Telegram

- **Раз в 2 часа** — один логический запрос графика у бота. Его ответ используется сразу для всех условий: новые интервалы, переносы и напоминание перед включением.
- Запрос графика состоит из двух обязательных действий меню: «ІНФОРМАЦІЯ ЩОДО ВІДКЛЮЧЕНЬ», затем лицевой счёт. Отдельного запроса для каждого интервала нет.
- **Раз в 10 минут** — чтение новых входящих сообщений из истории Telegram. Боту при этом ничего не отправляется. Подходящее отдельное уведомление о плановой перерыве разбирается сразу при таком чтении.
- Дополнительный запрос разрешён только для проверки времени включения, когда осталось не более 15 минут. Между любыми двумя начатыми запросами графика проходит **не менее 15 минут**, включая неудачные попытки и перезапуски. Любой такой запрос начинает новый двухчасовой отсчёт обычной проверки.
- При совпадении обычной проверки и проверки перед включением выполняется **один** запрос.
- Внутренний таймер просыпается раз в 15 секунд. Сам по себе он не обращается к Telegram: большинство проходов только проверяют сохранённое расписание. Ожидание ответа бота может немного задержать уведомление.
- При запуске можно использовать уже имеющийся полный ответ бота не старше двух часов, чтобы не запрашивать его повторно.

При выполнении двух шагов меню сервис несколько раз читает историю, ожидая ответ; это часть одного запроса, а не новые команды боту. Обычный неудачный запрос не повторяется каждую минуту. Если Telegram вернул `FLOOD_WAIT`, любые дальнейшие обращения откладываются на указанное им время. Ограничение частоты уменьшает нагрузку, но не является гарантией от ограничений Telegram.

## Тихое время и утро

В `.env`:

```dotenv
TIMEZONE=Europe/Kyiv
QUIET_HOURS_START=22:00
QUIET_HOURS_END=09:00
```

**С 22:00 включительно до 09:00 сообщения не отправляются.** Обычные проверки и чтение входящих продолжаются. Дополнительные запросы только ради уведомления о скором включении ночью не выполняются.

**Если до начала тишины стало известно об отключении на ближайшие тихие часы, предупреждение отправляется сразу.** Например, если в 20:00 получен график на завтра с отключением 06:00–08:00, сообщение придёт в 20:00, с датой следующего дня. Учитываются также интервалы, которые лишь частично пересекают тихое время. Действуют те же исключения причин и объединение пересечений.

Это не новая проверка бота: предупреждение строится по тому же ответу очередного запроса или входящему сообщению. Если интервал уже объявлен, повторного сообщения перед тишиной не будет. Изменение времени конца до начала тишины вызывает уведомление об изменении. После начала тишины отправка по-прежнему запрещена. Начало ровно в 09:00 не относится к тихим часам; о нём сообщит утренняя сводка.

В 09:00 сервис составляет актуальную сводку: что сегодня ещё ожидается и что уже идёт. Завершившиеся ночью интервалы пропускаются. Например, для начала в 09:30 сообщение будет: «Планове відключення електроенергії через 30 хв: з 09:30 до …». При запуске сервиса позже 09:00 актуальная сводка придёт после получения данных.

Перед каждой отдельной отправкой снова проверяется тихое время. Накопленная очередь не рассылается вслепую: устаревшие сообщения отбрасываются и пересчитываются по текущему расписанию.

## Если данные неясны

Сервис не угадывает время или тип отключения. Непонятный формат, ошибочная дата, неоднозначное время при переводе часов и неподдерживаемый статус записываются в лог. Непонятный ответ не затирает предыдущий успешно прочитанный график.

Новое сообщение и полный график об одном типе отключения с одинаковым началом считаются обновлениями одного события; более свежие данные заменяют время конца. Отдельная плановая перерва, которой нет в полном графике, сохраняется до указанного конца: само отсутствие в ответе не трактуется как отмена. Но **обещание скорого включения не отправляется, если свежий запрос не подтверждает конечное время**. Причина пропуска видна в логе.

При первом запуске читаются последние 100 сообщений чата. После этого сохранённый курсор позволяет дочитывать новые сообщения страницами без пропусков при большом количестве новых сообщений. Редактирования проверяются в последних прочитанных сообщениях; редактирование очень старого сообщения за пределами этой страницы может быть обнаружено только через актуальный ответ бота.

## Настройка и вход

Нужны Bun 1.3+ и `flock` из util-linux. У Telegram-аккаунта должно быть право писать в канал назначения.

```bash
bun install --frozen-lockfile
# Только при первоначальной установке, если .env ещё нет:
cp .env.example .env
```

Заполните в `.env` пару `TELEGRAM_API_ID` / `TELEGRAM_API_HASH`, `BOT_ACCOUNT` и название канала. API-реквизиты выдаются на https://my.telegram.org в разделе API development tools.

```dotenv
TARGET_TITLE=😱AAA
BOT_COMMAND="ІНФОРМАЦІЯ ЩОДО ВІДКЛЮЧЕНЬ"
BOT_ACCOUNT=ваш_9_значный_лицевой_счёт
```

При совпадающих названиях каналов укажите `TARGET_ID` — положительный Telegram ID без `-100`. Вместо `BOT_COMMAND` поддерживается `BOT_BUTTON`, но одновременно задавать оба нельзя.

Вход по QR-коду:

```bash
bun run login:qr
```

На телефоне: Telegram → Настройки → Устройства → Подключить устройство. Отсканируйте QR в терминале. Если включена двухэтапная аутентификация, введите облачный пароль Telegram; его ввод в терминале виден.

Другой вариант — `bun run login`: код приходит способом, выбранным Telegram. `/resend` доступен только при наличии предложенного Telegram запасного способа и после его таймера.

## Запуск и управление

В текущей установке сервис называется `electrobb.service`.

```bash
systemctl --user status electrobb
systemctl --user restart electrobb   # в том числе после изменения .env
systemctl --user stop electrobb
systemctl --user start electrobb
```

Ручной запуск (предварительно остановите сервис):

```bash
bun run start      # постоянный процесс
bun run once       # один проход правил; может отправить настоящие уведомления
bun run preview    # прочитать последний график и показать расчёт, без команд боту и отправок в канал
bun run inspect    # посмотреть последние сообщения и кнопки бота
bun test           # автоматические тесты, без сети и реальных отправок
```

`once` соблюдает интервалы запросов и тихое время, а не принудительно делает новый запрос. `preview` — расчёт на последнем ответе из истории, который может быть устаревшим; это не проверка актуальности и не изменение рабочего состояния.

Все команды через `run.sh` защищены общей файловой блокировкой. Если сервис уже работает, ручная команда завершится с кодом 75. Для входа или просмотра через скрипт сначала остановите сервис, после работы запустите снова. Читать логи можно без остановки.

Установка автозапуска на другой машине:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/electrobb.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now electrobb
loginctl enable-linger "$USER"
```

В шаблоне используется путь `%h/work/electrobb`. `run.sh` находит Bun в PATH или `~/.bun/bin/bun`; при другом расположении задайте `BUN_BIN` в сервисе. Автозапуск и linger позволяют работать после перезагрузки и без открытого пользовательского сеанса.

## Где смотреть логи

Живой журнал сервиса:

```bash
journalctl --user -u electrobb -f
```

Последние события и ошибки:

```bash
journalctl --user -u electrobb --since today --no-pager
```

Также сервис пишет структурированные JSON-строки в `logs/YYYY-MM-DD.jsonl`. Дата файла и поле `time` — по Киеву. Файлы старше 30 дней удаляются автоматически.

```bash
tail -n 100 logs/2026-10-23.jsonl
rg 'notification_sent|operation_failed|query_started|query_deferred' logs/
```

Основные события:

| Событие | Что объясняет |
| --- | --- |
| `bot_message` | Полученный текст, ID и время сообщения |
| `parsed` | Найденные интервалы, исключённые причины, неизвестные типы и ошибки разбора |
| `snapshot_reused` | Почему свежий готовый ответ использован без повторного запроса |
| `query_started` / `query_succeeded` | Зачем запросили график и что сохранили |
| `query_deferred` | Почему запрос отложен ограничением частоты |
| `notification_decision` | Объединённые интервалы на сегодня и ближайшее тихое время (`quietIntervals`), кандидаты сообщений и причины пропуска |
| `notification_sent` | Что действительно отправлено в канал |
| `outbox_dropped` / `send_suppressed` | Почему ранее подготовленное сообщение больше не нужно |
| `operation_failed` | Ошибка Telegram, сети или разбора |
| `tick_skipped` | Работа приостановлена по требованию Telegram |

Например, `quiet_hours` означает тишину, `no_new_or_due_notifications` — повторять нечего, `no_remaining_outages_today` — актуальных интервалов на сегодня нет, `end_reminder_waits_for_fresh_query` — время включения ещё не подтверждено свежим ответом.

Логи содержат исходные тексты бота, в том числе адрес и лицевой счёт. `.env`, `cache/` и `logs/` исключены из Git. Файлы создаются с ограниченными правами; API hash, коды входа и пароль 2FA в журнал не записываются. Сессия `boobabb` не изменяется.
